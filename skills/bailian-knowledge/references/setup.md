# 接入自己的资料

## 从当前任务进入

用户无需学习 `init`。围绕“选哪些资料、以后用来做什么”推进；能从当前任务判断的用途不重复问。一次性附件任务直接处理，不先安装或建库。

长期接入意图出现且无相关绑定时，可以简短说明：

> 可以把这批培训资料接入资料库，以后准备课程或查资料时直接参考。接入需要上传选定文件，云端知识库会持续计费。你希望使用百炼还是其他服务？

已经选择百炼或有适用的既有授权时跳过服务商选择。未回应、拒绝或选择其他服务则继续本地可完成的工作，不调用百炼、不反复引导。不要把安装 Skill 或“这些资料以后有用”解释成云端上传与持续费用授权。

若用户一开始就要求使用百炼接入资料，可直接准备计划；无需先重复询问“要不要用百炼”。计划确认必须基于实际范围，不能只给抽象的“可能收费”提示。

## 发现资源与准备计划

1. 读取 [资料绑定](bindings.md)，区分未配置、已有 active、paused 和未完成的 initializing。先复用用户指定或已绑定的资源；用户明确要求新建时为本次新库准备独立记录，不以复用替代新建。本次初始化已有 checkpoint 时仍应恢复，不能重复创建。
2. 读取 [共享协议](../../bailian-protocol/SKILL.md) 并完成预检。通过已支持的鉴权状态、配置与资源查询了解可用 Workspace；有歧义只询问必要的选择，不要求用户先抄全部资源 ID。缺凭证时按协议引导本机登录，不索要聊天中的密钥。
3. 读取当前入口 introspect，核对 init、上传/导入、同步、服务查询和检索能力。未提供的能力不得猜测执行；缺权限或服务未开通时如实说明。
4. **数据集默认复用，知识库按用途选择。** 数据集（collection）是数据中心文件容器，知识库承载可检索索引，检索服务提供查询入口。当前 init 使用默认分类，不创建数据集；不要为了个人接入另跑 `collection create`。
5. 用户选择已有知识库时只读核对它及匹配服务；已有服务则验证复用，缺检索服务则按 schema 补建并测试 beta。不要为了补服务调用 init 新建另一个库，也不随意覆盖已有服务配置。仅在确需新知识库时使用 init。
6. 新库流程使用具体用途名称、Workspace 和稳定 state-file 执行 `init --dry-run`。它可能鉴权并读取远端资源，但不创建、修改、删除资源或 checkpoint，也不执行样例检索。init 的复用依赖自身状态与资源核对，不能声称它会自动接管任意同名旧库。
7. 核对用户选定文件或目录的实际范围。不要把整个主目录作为默认上传范围；不上传凭证、密钥、绑定或 checkpoint 文件。目录含不应上传的文件且当前命令不能过滤时，改用具体授权文件或请用户缩小目录，不编造排除参数。

在本次接入范围内向用户展示具体资料、用途、新建/复用资源、上传范围及费用。普通用户不必理解数据集或 beta 等实现细节，除非影响选择；资源标识仍应保存到绑定及清理记录。

## 费用与确认

使用 CLI 预览提供的官方计费链接和实际规则。当前规则说明必须保留：**知识库创建成功即持续按时计费，即使没有检索也一样。标准版 720 小时为一次性免费额度，多个知识库共享，新开通后有 30 天有效期；模型调用另计。** 不知道账户剩余额度就说未知，不承诺免费。后续若 CLI 规则更新，以核实后的规则为准。

面向用户的计划示例（替换为本次实际范围）：

> 我会把你选定的培训目录接入「课程资料」，用于以后备课和查证。接入后，相关备课和查证任务中我会直接检索这些资料，你也可以选择每次明确要求时才查。本次需要新建一个云端知识库，文件会上传到百炼。新库创建后持续按时计费，导入和模型调用可能另收费，当前可用免费额度未知。确认后我会完成接入，再继续准备这次课程提纲。

结合预览补充具体计费规则和链接，而非只照抄示例。计划明确包含以后相关任务自然检索，且用户同意后才记录 `read: relevant_tasks`；用户只授权本次接入或未确定日常读取方式时记录 `on_request`。用户已了解并授权同一范围时直接执行；仅说“体验一下”或选择百炼，不等于知情同意持续计费。只有适用授权存在时才加 `--yes`；退出码 7 是正常确认流程，不作为 bug 上报。新出现的替换、删除或明显扩大范围须准备变更计划，已有授权未覆盖时再确认。

## 首次新建并上传当前目录

适用于“新建一个知识库，把当前文件夹上传进去，再设计几个问题验证召回”。已选择 bl / 百炼时不再询问服务商。按下面顺序完成整条链路，不能停在 init 样例成功。

1. **固定目录和资料范围。** 用宿主确认用户所指当前目录的绝对路径；不能拿 Skill 安装目录或执行工具临时切换后的目录代替。扫描文件与子目录，记录相对路径、类型、待上传/排除及原因。当前 `doc sync` 递归扫描，排除 `.git`、`node_modules`、`.bailian` 和 checkpoint 相关文件，跳过符号链接、不支持的类型及音视频；以实际 schema 和扫描结果为准。它没有通用排除 flag，也不承诺遵循 `.gitignore`。Agent 仍须检查凭证等不应上传的内容，不能把扩展名受支持当作安全。不能过滤时改用具体授权文件的逐文件上传，或让用户缩小目录；禁止直接同步包含敏感文件的原目录。
2. **在检索前制定验收问题。** 阅读待上传资料，按下节建立问题与预期命中表。无法可靠读取的文件标为“未建立内容验收预期”，不能编造内容。没有可上传文件时先报告并停止新建；没有任何可验证内容时先说明限制并补齐可读资料，不先创建计费资源。
3. **预览新建计划并确认。** 完成上述鉴权、Workspace 和 schema 核对，使用用途名称与稳定 state-file 执行 `knowledge init --dry-run`。展示目录、拟上传文件及跳过项、用途、验收范围和实际费用，按已有授权或用户确认推进。此时目标库尚不存在，不能声称已完成针对新库的 sync 远端预览。
4. **初始化新库及检索服务。** 需要个人绑定时先保存 `initializing`，再按确认计划执行 init；显式资源管理请求不强行建立个人绑定，但仍保留 checkpoint 和恢复信息。记录返回的 index ID、agent ID、beta 版本及新建/复用资源。init 创建知识库、准备 beta 检索服务并检索内置样例，不导入当前目录、不创建问答服务、不自动发布服务；不要再额外执行 `knowledge create` 建第二个库。
5. **上传真实资料并等待入库。** 读取 [维护与恢复](maintenance.md)，对已确认的绝对目录与新 index ID 执行 `knowledge doc sync --dry-run`，核对 actions、skipped、conflicts 和 blocked，再执行同一计划。初次上传不带 `--delete`。预览范围和已授权范围一致时不重复确认；新增范围、替换或删除未被授权时才另行确认。若改用逐文件上传，则按 schema 等待入库终态。保存 file/document ID 与本地路径的实际关联，逐项核对成功、失败、pending 和跳过状态；退出码 0 或上传回执不能代替入库就绪。
6. **逐题验证用户资料。** 使用实际 agent ID、已核实的服务绑定范围和 beta 版本调用 `knowledge search`，按下节对照原文件预期。index ID 不能当 agent ID；不能用 init 样例命中代替验收。不要为验收擅自发布服务、创建 chat 服务或调整索引配置。
7. **报告并收尾。** 报告确认范围内文件总数、入库成功数、失败/pending 数与跳过项，并输出逐题结果和总判定。仅当确认范围内全部文件就绪且全部验收问题通过时，才报告“本次接入与抽样召回验收通过”，需要的绑定此时设为 active 并更新验证时间。继续完成用户原任务；只要求接入时交付验收报告及后续使用方式即可。退出或暂停不会停止计费。

## 多问题召回验收

**先定预期，再看结果。** 默认设计 3–5 个不同问题；用户指定数量或问题时优先遵守。尽量覆盖不同文件、主题和关键事实；仅有一份文件时覆盖不同段落或事实，避免把同一问题换几个说法充数。资料不足以支持 3 个独立问题时如实说明，使用全部可验证问题并明确覆盖限制，不编造问题。大量文件采用代表性抽样，说明哪些文件已做内容验收、哪些只核对入库状态。

在首次检索前填写前三列，预期来自本地原文件，不能看到命中结果后反向改题或改预期：

| 问题                       | 预期来源                       | 必须命中的内容                               | 实际召回证据                        | 判定                       |
| -------------------------- | ------------------------------ | -------------------------------------------- | ----------------------------------- | -------------------------- |
| 根据原文提出的自然语言问题 | 相对路径及可用的章节/页码/段落 | 可核对的事实、数值、条件或步骤；列全必要信息 | 实际返回文档/ID、片段与排名（若有） | 通过 / 失败 / 未验证及原因 |

- **单题通过：** 本次返回的片段来自预期文件或预先记录的等价来源，并在一个或多个片段中包含全部必要信息，能直接支撑回答。同名文件要用上传关联的 ID 消歧，不能仅凭文件名推断来源。可接受语义等价表达，不要求逐字相同。
- **不算通过：** 仅命中标题、同主题但缺少必要事实、仅命中内置样例、无结果，或凭模型常识补出答案。相似度分数高也不能代替内容核对，不设未经验证的通用分数阈值。API 错误、无法读取预期或来源无法确认记为未验证，保留原始含义。
- **总体验收：** 固定的验收问题全部通过，且确认范围内全部文件已入库就绪。任一失败或未验证都不能声称整体通过；报告通过数/总题数与缺口。抽样通过不保证所有文档或未来所有问题均可召回。
- **失败后处理：** 先核对入库终态、Workspace、服务所绑定知识库及版本。每题最多做两次有依据的改写重试，保留原始问题、预期和每次结果；改写成功标明“原问未通过，改写后通过”，原问仍计为未通过。不删除失败题、降低预期或改用其他库来凑通过。服务/配置变更需按实际范围处理授权；修复后复测原始问题集。

## 跳过、部分完成与恢复

跳过与上传失败分别统计，不能把它们藏进“全部成功”。列出跳过文件的相对路径和原因；被整体排除的目录可按目录列明，不能把一个目录条目当成一个文件计数。敏感文件只说明路径/类别和处理方式，不展示秘密内容。清单较长时回复摘要并提供可查看的完整清单，清单与验收材料不放入待同步目录或个人绑定正文。

预览阶段已说明且用户接受的排除项不进入本次确认的上传范围；最终仍须列出，并明确“确认范围已完成，以下文件未上传”。用户要求所有文件但仍有未处理的格式或文件时，只能报告部分完成，并给出按当前能力可用的单文件处理或缩小范围选项，不自动排除后声称整个目录完成。

资料导入部分失败、存在 pending 或召回验收未通过时，已有个人绑定保留 initializing，不推进全量验证成功时间。可以在已授权且服务范围核实的成功子集内临时检索并交付任务，但必须说明资料不全或验收未通过。只有用户明确缩小范围后，才按新范围重新核对并重做验收。

初始化或写入失败时，保留原始输出、checkpoint 和已知资源，按 [维护与恢复](maintenance.md) 核对并续接，不改名重建、不盲目重放创建。报告已产生或尚不确定的资源、持续费用及清理方法，不把失败说成资源不存在。

用户只要求样例体验时可按 init 样例结果结束，但不得称为用户目录接入或多问题验收成功。
