# 更新、恢复与清理

## 上传与按需同步

读取 [资料绑定](bindings.md)，核对本次用户指定目录/文件、知识库与 Workspace。读取授权不等于写入授权；用户让你写出的草稿、当前聊天或临时附件不自动保存到云端。

当前 schema 提供目录同步时才能执行。沿用已有目录、目标、stateFile 和 syncId，先 dry-run，向用户说明新增、替换、不变、保留与删除的项目及导入模型费用。内容更新也会删除旧索引版本；有适用范围授权再执行，只有新增且无其他高风险操作时不额外索要删除确认。

- 默认保留本地已删除文件对应的远端文档。仅在用户要求远端同步删除且范围明确时启用 `--delete`。“保持一致”不意味着清理知识库里全部其他文档；同步仅管理当前同步集，手工上传和其他同步集不进入删除范围。
- 保留本地 checkpoint，不手改或删除它来绕过冲突；CI 也应持久化它。同一同步集只有一个写入者，多宿主或多机器不并发执行。
- 文件改名按新路径新增、旧路径保留或显式删除处理，不承诺自动识别。新版本入库成功后才能删除旧索引；执行依赖 CLI 的恢复流程，不自行改变顺序。
- 完整成功后记录 `last_success_at`。部分成功不能推进全量成功时间；说明 pending / failed 项与已可用范围。最近一次同步成功不保证此后本地没有变化。
- 不完整的本地扫描、远端清单或关联不能作为删除依据。状态丢失时可核对远端标记，但不能按文件名猜关联或承诺完整恢复。
- 宿主没有调度或后台能力时只在本次执行，不说“以后会一直自动同步”。要新增目录或监控任务应另行明确范围，不能由本 Skill 暗中创建。

## 初始化或写入失败

创建超时、响应丢失可能已经产生云端资源。保留原始输出，先读 init/sync checkpoint 和已记录资源，再核对远端；不知道结果就报告不确定，不盲目重放创建，不改名重建。若当前 CLI 缺少可关联的 ID/标记或可靠查询能力，停止写入，保留未知项，说明需要用户协助在控制台或服务支持中核对；名称相同不证明是本次资源。

任一步失败先查看已完成和 pending 项，按实际 CLI 能力恢复。绑定保留已知资源并保持 initializing；不能因命令失败就说资源不存在。列出已创建资源、仍可能持续的费用与清理方法，复用资源单独说明。

检索失败时可以继续完成不依赖历史资料的部分，但说明没有验证的事实，不伪造来源。不要静默改用另一个库、账号或服务商来掩盖失败；服务端错误原样保留其含义。

## 暂停、断开与停止收费

- “这次别用历史资料”：本轮不查、不引用缓存，不改持久状态。
- “暂停使用某资料库”：持久标为 paused，停止自动读取/同步，丢弃会话使用缓存；不删除资源，不停止计费。明确恢复时核对原绑定，不补传暂停期间文件。
- “断开/移除绑定”：说明只移除本地关联不会删除云端资料或停止计费，保留用户可用的资源 ID 与清理方式；不要把移除配置报告成云端删除。
- “停止收费/结束体验”：检查具体云端资源与清理范围；删除知识库成功才能停止其规格计费。删除所有文档、删检索服务、暂停或退出终端均不能替代它。

## 清理实际资源

用户要求清理时，展示本次新建资源及具体 ID、归属和删除后果。复用资源不进入默认清理范围；用户明确要求删除复用资源时，应单独核对其授权范围和其他用途。已有删除授权覆盖具体对象时直接执行，否则在具体计划上确认。

使用 CLI 返回或当前 schema 的实际删除路径；展示给用户的清理指令不自动携带 `--yes`。不可假设删除知识库会连带删除所有文件与服务。

索引文档删除不代表数据中心源文件删除；源文件清理需另核对它未被其他知识库使用及删除范围，无法确认则保留并说明。默认数据集是复用资源，不清理；当前无数据集删除 API，不编造 `collection delete`。

逐项验证删除结果，更新绑定；失败或未知项保留 ID、在绑定写入 blocked_reason、停止自动调用并说明后续办法。无法确认删除成功就不能说“已停费”或“已全部删除”。保留必要清理信息，不把状态文件删除当作恢复或停止计费的方法。
