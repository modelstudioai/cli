# 个人资料绑定

## 存放与边界

路径：`~/.bailian/personal-knowledge/config.json`，Windows 使用当前用户主目录。这是 **Skill 自己管理的文件**，由宿主文件工具读写；不是 CLI 已有配置键，不使用 `bl config set` 写它。`init` / `doc sync` 不自动维护这份绑定。

只记录路由、范围、授权、资源 ID 与状态文件路径，不存密钥、签名 URL、资料全文或检索缓存。不写入工作仓库或 Skill 安装目录。宿主能访问同一用户文件时才可跨会话复用；无文件工具或 CLI 能力时说明缺失能力，不承诺已启用或跨宿主可用。

读取不存在的文件不创建资源。损坏、未知版本、范围缺失或非法状态时停止自动云端操作，保留文件并核对恢复，不覆盖或重建来掩盖问题。

## 格式

顶层包含 `schema_version: 1` 与 `sources` 数组，无默认知识库字段。每个 source 代表一个用户能识别的资料用途；使用首次创建并持久保存的 UUID 作 `id`，不把当前目录或库名当唯一身份。

| 字段                    | 含义                                                                                                                                                                                         |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`, `name`, `purpose` | 稳定本地标识、用户可理解的资料名、覆盖的客户/项目/主题和使用目的                                                                                                                             |
| `blocked_reason`        | 自动调用阻塞原因，正常时 null；范围失效、权限变化或删除状态未知时记录具体原因与实际时间，保留原 status                                                                                       |
| `status`                | `initializing`、`active` 或 `paused`                                                                                                                                                         |
| `product`               | `bl` 或 `kscli`，按当前实际可用入口记录                                                                                                                                                      |
| `scope`                 | `workspace_id`、实际 API `endpoint_origin`、当前 `config_profile`（默认 profile 可为 null）；不存凭证                                                                                        |
| `index_ids`             | 已验证且授权检索的知识库 ID 数组；单库也是数组，不按同名自动合并                                                                                                                             |
| `retrieval`             | `agent_id`、实际 `agent_version` 与 `scene`；通常为 search。版本取实际值，init 返回 beta 就保存 beta                                                                                         |
| `local_sources`         | 用户允许接入的绝对文件/目录路径；纯已有云端资料可为空                                                                                                                                        |
| `consent`               | 实际授权时间 `confirmed_at`、`provider: "bailian"`、`read: "relevant_tasks"` 或 `"on_request"`、允许上传的 `upload_paths`、`sync: "on_request"`、本次具体计费/替换/删除授权摘要 `risk_scope` |
| `init_state_file`       | 本次新建流程使用的绝对 checkpoint 路径，复用已有资源可为 null                                                                                                                                |
| `sync_sets`             | 各同步集的 `directory`、`index_id`、`state_file`、CLI 实际返回的 `sync_id` 与 `last_success_at`；不手工伪造同步 ID                                                                           |
| `resources`             | 实际观察到的资源 kind / id / created-or-reused，供恢复和清理使用；复用不能改写为本次创建                                                                                                     |
| `last_verified_at`      | 资料检索验证成功时间；不等于源文档更新时间                                                                                                                                                   |

未完成的 ID、时间等字段保持 null 或空数组，不填示例值。授权摘要应明确实际范围；`read: "relevant_tasks"` 仅在用户同意相关任务中自然取用资料后记录，否则默认 `on_request`，只按明确请求读取。例如“参考 A 客户旧方案”属于明确请求；仅“帮我写 A 客户邮件”不等于要求使用历史资料，只有 `relevant_tasks` 才可据相关性自然检索。上传路径只允许用户确认的范围，不能因读授权自动增加；`risk_scope` 只复用覆盖同一操作、目标与范围的授权，不是无限期删除或计费许可。

此文件不保存 collection ID 作为知识库 ID。默认复用数据集（collection）与默认分类；只有用户明确选择了非默认分类且命令支持时，才在相应同步记录补充实际 category ID。

## 创建与更新

1. 已有匹配绑定时优先复用。新接入可先在内存中分配 UUID 和稳定路径进行只读预览；用户确认实际计划后，在任何云端写操作前保存 `initializing` 与范围，避免创建后丢失关联。
2. 初始化 checkpoint 建议固定在用户目录 `~/.bailian/personal-knowledge/states/<source-id>/init.json`；同步 checkpoint 为该 source 下各目录分别分配稳定路径。传入 CLI 的 `--state-file`，不依赖会话工作目录。已有 CLI checkpoint 必须沿用原路径，不搬迁或改写内容来接管其他资源。
3. CLI 写自己的 checkpoint；Skill 只保存引用和真实返回结果。各步成功或部分失败后记录已知资源。知识库 ID、检索服务和版本必须从返回或只读核对得到，不从名字猜测。
4. 在个人资料导入与检索验证成功后设为 `active`。纯连接已有资料也需验证服务类型和覆盖范围。用户只授权样例体验时，不默认开启日常自动检索。
5. 更新前重新读取，保留其他 sources。采用宿主支持的原子替换，尽可能限制为当前用户读写；遇到并发变动先重读合并，无法安全合并则停止写入。同一资料的接入/同步串行执行，不保证多宿主并发安全。

若宿主无法保存绑定，告知只在本次会话可用，保留实际资源及恢复方式；不说跨会话接入完成。不能写暂停状态时，当前会话立即停止取用并说明尚未持久暂停。

## 复用、恢复与失效

- 每次新会话首次相关任务读取配置，按 purpose 选择资料。用户显式选择其他工具或资料时尊重选择，不双写或自动迁移。
- 新会话首次调用绑定服务前，只读核对记录的 scope、服务类型、版本及所绑定知识库范围；同一会话可复用核对结果，范围或配置变化后刷新。存在额外未授权知识库时，仅在当前 schema 支持且能可靠限定到授权 index_ids 时检索，否则先处理范围问题。
- 检索服务返回不存在、权限变化、已知账号/端点变更或服务范围无法可靠限定时，保存 `blocked_reason` 并停止该绑定的自动操作；不以同名库替换，不将旧 ID 发往新的 Workspace/端点。核实前不能新建一套来“修复”。用户明确要求核对/修复后才只读复验；问题解决后清除 blocked_reason，用户主动 paused 的仍保持暂停。无法写入时停止当前会话调用并说明阻塞尚未持久保存。
- `paused` 仅在明确恢复后核对并恢复；资料不完整则转回 `initializing`。暂停不清除恢复记录、不删除云资源、不停止计费。
- 取消本轮历史资料使用不改持久状态。删除云资源后更新或移除相应绑定，防止后续自动调用已删除的 ID；云端状态未知时保留记录并写入 blocked_reason，停止自动调用。
- 只有 CLI init/sync checkpoint、没有个人绑定时，不推断持续检索授权。用户选择百炼后可只读核对原资源，明确用途与使用范围再建立绑定；无需为此重新初始化。
