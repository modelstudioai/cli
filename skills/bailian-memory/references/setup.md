# 首次启用与本地身份

## 先复用，再引导

用户明确要求启用，或个人记忆意图触发后的状态检查发现未配置时，进入此流程。首次触发先完成下面的告知和启用选择，不要因缺少配置就直接绕过 Skill。用户拒绝或尚未回答时不索取 Workspace/API Key，本会话不重复询问；暂停状态不自动重新引导。

用户同意启用或已有有效授权后，再读取共享协议及其 setup/versioning 资源。按协议完成版本预检，用 `bl auth status --output json` 和 `bl config show --output json` 检查现有配置；输出中的凭证已遮罩，不直接读取凭证文件或打印环境中的密钥。共享协议缺失时明确说明依赖未安装并引导补齐，不假装完成初始化。

首次启用说明：

> 启用后，我会把选定的生活和工作对话片段发送到百炼云端，保存长期记忆和基础资料，可能产生费用。普通个人信息会自动记忆；敏感信息只有你明确要求时才保存，密码和密钥不保存。你可以随时暂停。目前能删除事实记忆，但暂不支持精确删除画像中的单项资料。是否启用？

用户已在当前对话知情授权则沿用，不重复询问。未授权不创建 Schema、不上传对话。

例如用户问“你知道我叫什么吗”，而本服务尚未启用，可以回答：“目前我还没有通过百炼记忆读取到你的称呼。可以启用云端个人记忆，让我以后记住你的资料和偏好……”然后给出上面的必要告知。没有执行检索时不能说“我查过记忆库，没有找到”。用户确认前说出的信息不自动批量补传；初始化完成后，只有当前仍适用且已获授权的明确保存请求才继续处理。

- 已有 Workspace：展示拟使用的 ID，在启用范围内复用，不擅自改全局配置。
- 缺 Workspace：请用户提供 ID，保存到本 Skill 配置；每条 Memory 命令显式传入。无需用户提供 library/project。
- 缺 API Key：提示不要粘贴到聊天。普通百炼账号可通过 `bl auth login --console` 完成浏览器登录；已有 Key 的用户在本机终端按 `bl auth login --help` 配置。由用户输入密钥，Agent 不索取、代填或回显。订阅凭证不要假定能访问 Memory，以只读验证结果为准。
- 登录完成后重新检查 auth status；凭证存在不等于能访问 Workspace 或已开通记忆服务。

不要先索取 Workspace/API Key 再说明上传范围。仅用默认规则 list 做只读服务验证，不为了测试权限写入个人事实。

## 配置格式

路径：`~/.bailian/personal-memory/config.json`（Windows 使用当前用户主目录）。这是 Skill 自己的文件，不是 `bl config set` 的配置键。使用宿主可用的文件工具，尽可能限制为当前用户可读写；不存进工作仓库或 Skill 安装目录。

```json
{
  "schema_version": 2,
  "status": "initializing",
  "workspace_id": "<用户确认的 Workspace ID>",
  "user_id": "<首次生成并持久保存的 UUID>",
  "library_mode": "default",
  "project_mode": "default",
  "profile_schema_id": null,
  "profile_schema_version": 1,
  "consent_version": 1,
  "consented_at": "<实际授权时间的 ISO 8601 值>",
  "sensitive_memory_policy": "explicit_only"
}
```

示例中的尖括号值必须替换为真实配置，不是默认值。文件中不存密钥、对话、Profile 副本。创建前检查是否已存在；安全写入，不覆盖无法识别的配置。损坏或版本不支持时暂停并请求恢复，不默默重建身份。状态变更采用写入临时文件后替换等宿主支持的安全方式。

## 状态与旧配置

| 状态                 | 判断与操作                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------- |
| 未配置（文件不存在） | 提出一次启用引导，未授权不创建云端资源                                                            |
| `initializing`       | 用户已同意启用但步骤未完成；复用已有 user_id 和 Schema ID，按下述步骤核对后续接，失败仍保持此状态 |
| `active`             | 范围、身份、Schema 和授权完整，允许约定范围内自动读写                                             |
| `paused`             | 用户暂停或遗忘限制导致暂停；只接受明确的恢复请求，不自动续接                                      |

v2 用 status 作为唯一状态，不同时维护 enabled。initializing 只允许已授权的配置验证和初始化操作，不自动抽取日常聊天。用户在初始化途中要求暂停也设 paused；再次明确恢复后，如初始化条件不齐，则转 initializing 完成缺失步骤。

旧 schema_version=1：保留身份和资源 ID。enabled=true 且必要字段完整时可迁移为 v2 active；enabled=false 无法单独区分初始化未完成和主动暂停。若当前上下文有明确状态证据，按证据迁移；否则保持停止自动操作，询问用户要继续初始化还是保持暂停，不能猜测恢复。迁移成功后移除 enabled。未知版本、字段不全却标记 active、非法状态或配置损坏时停止并修复，不能另建身份掩盖问题。

## 完成启用

1. 获得启用授权后设 status=initializing。先保存身份，避免后续失败导致 user_id 改变。
2. 用已绑定 Workspace/user_id 调用默认范围的 `memory list --page-size 1 --output json`。鉴权/权限/服务错误原样说明，不尝试更换账号或库。
3. 读取 [基础画像](profile-schema.md)，创建本配置专用的模板，保存返回的 profile_schema_id。已有 ID 则 profile show 验证复用，不每次创建。创建失败保持 initializing；响应不确定时先 list/show 核对，不盲目再次创建。
4. profile get 验证同一 user_id 下资料可读取（初始为空正常）；完成后 status=active，说明开始使用及暂停方式。

同一台机器不同宿主共享这个文件时可复用身份，但不保证宿主能访问同一路径。不要并发初始化。Schema 使用个人 user_id 派生的唯一名称；无可靠依据时不能接管相似名称模板。

## 恢复、范围变化与停用

- 暂停仅改 status=paused，不删除云端数据；明确恢复时仍用原身份，检查完整性和可访问性后设 active，未完成初始化则续接 initializing。宿主不能写配置时不能宣称已持久暂停，应说明限制并停止当前会话的自动操作。
- 迁移设备需用户显式转移配置、配置凭证并核对 Workspace。不自动合并已有身份。
- 账号、Workspace 或默认库发生已知变化时暂停确认。不重用旧 Schema ID 到新的范围。
- 省略 library/project 会跟随服务端默认值；当前没有可用命令可靠解析并监测默认库切换，因此不能保证检测所有切换。不自动创建库或规则。
- user_id 只是数据范围标识，不是认证凭证或权限隔离机制。
