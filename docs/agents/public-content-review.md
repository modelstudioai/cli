# 公开内容检查

## 触发条件

- 分支合并或公开前检查敏感内容。
- 删除误提交的内部资料、凭证或真实环境信息。

## 必查清单

### A. 当前文件

- [ ] 用 `git ls-files` 确认公开范围；忽略规则不影响已跟踪文件。
- [ ] 检查凭证、私钥、签名 URL、真实 Workspace/服务/文件 ID、个人路径和个人资料；报告只列位置，不复述敏感值。
- [ ] 内部需求、评审草案、执行日志及提测交接资料保存在内部文档系统；公开仓库只保留面向用户或贡献者的说明。
- [ ] 删除内部协作文档链接后检查引用；不得将内部链接复制到提交说明或公开报告。
- [ ] 测试数据使用虚构或脱敏内容，图片使用有明确公开使用依据的素材。

### B. 提交历史

- [ ] 检查分支独有提交及已删除文件；删除最新文件不等于清除历史。
- [ ] 重写前确认基线、远端状态、其他分支和工作树；保留本地恢复手段，不把包含旧资料的备份推送到远端。
- [ ] 验证清理后的历史不再包含目标文件和敏感值，且业务源码与清理前一致。
- [ ] 更新共享远端历史前取得明确授权，使用指定旧提交的 `--force-with-lease`；其他引用和托管平台缓存单独处理。
- [ ] 发现真实凭证时先撤销或轮换；历史清理不能代替失效处理。

## 完成后自查

- 执行 `git diff --check`，检查文档引用和待提交范围。
- 扫描当前树及待公开提交的内容，分别记录检查范围和未处理的远端引用。

## 常见漏点

- `.gitignore`、删除提交、squash merge 都不会自动清理已公开的旧分支或 PR 引用。
- 资源 ID 不是访问凭证，但真实环境标识和服务配置仍应脱敏。
