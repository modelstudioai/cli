# 知识库迭代二：产品设计

日期：2026-09-25 · 状态：设计草案，供产品评审

本文说明用户要解决什么问题、怎么使用、会看到什么结果。实现任务另见[开发计划](../plans/2026-09-24-knowledge-iteration-2.md)。下文命令和终端输出均为拟议体验，示例 ID 不代表已创建资源。

## 1. 我们希望交付什么

让个人用户能够放心地开始使用知识库，把本地资料持续更新进去，并通过 AI 助手完成日常操作。

用户应该能回答四个问题：

1. **我能用起来吗？** 不必先到控制台抄一组资源 ID，就能完成第一次成功检索。
2. **我的资料更新了吗？** 修改本地目录后，能看清知识库将发生哪些变化，再执行同步。
3. **助手知道怎么操作吗？** 助手能够查询当前 CLI 支持的能力和参数，而不是猜命令。
4. **我会付多少钱、如何停止？** 创建前知道存在持续计费，体验后知道哪些资源仍然存在、如何清理。无法查询实际费用时明确说明未知。

本期对应[原始需求文档](https://alidocs.dingtalk.com/i/nodes/m9bN7RYPWdyrPBREcjaar7XvVZd1wyK0)的第 5–8 项，并加入计费提醒。

| 能力                    | 用户得到的价值                             | 主要使用者             |
| ----------------------- | ------------------------------------------ | ---------------------- |
| 初始化 `init`           | 一条命令完成首次检索，不用手动串联建库步骤 | 初次体验者             |
| 目录同步 `doc sync`     | 本地资料更新后，按需更新知识库             | 持续维护资料的人       |
| 命令发现 `--introspect` | 获取当前版本实际支持的命令和参数           | AI 助手、工具开发者    |
| 个人知识库 Skill        | 用自然语言完成初始化、同步、查询与清理     | 使用 AI 助手的个人用户 |

以下以 `kscli` 举例。两种入口共享行为，但路径由各自命令表决定：`kscli init` 对应 `bl knowledge init`，`kscli doc sync` 对应 `bl knowledge doc sync`，`kscli kb create` 对应 `bl knowledge create`。不能机械地加前缀转换所有命令。

## 2. 用户旅程

```mermaid
flowchart LR
    A[配置访问凭证与工作空间] --> B[了解计费并确认初始化]
    B --> C[样例检索成功]
    C --> D[同步自己的资料]
    D --> E[检索或使用已有问答服务]
    E --> F[资料变化后再次同步]
    F --> E
    C --> G[结束体验：查看并清理新建资源]
    E --> G
```

“一键初始化”的前提是已经具备可用的 API Key、工作空间和服务权限。本期解决创建、导入和检索的串联，不承诺替用户完成账号注册、开通服务或授权。

## 3. 首次体验：从 init 到第一条结果

### 第一步：说明即将发生什么

用户执行：

```sh
kscli init
```

如果缺少凭证或工作空间，给出具体配置指引；具备前提后，展示创建计划和计费说明，在用户确认前不创建资源。

拟议输出：

```text
准备初始化知识库体验

将在当前工作空间中：
  上传一份内置样例文档
  创建知识库 cli-demo
  创建检索服务，并验证一次样例检索

费用提醒
  知识库创建成功后，即使不检索，也会持续按运行时长计费。
  标准版的一次性免费额度有有效期，多个知识库共享扣减。
  模型调用费用另计；当前账户剩余额度尚未核实。

确认上述操作后，请执行：kscli init --yes
```

提醒旁附完整计费规则链接。使用 `--dry-run` 时可查看计划；它可能读取现有资源，但不创建、修改或删除资源，也不运行样例检索。

### 第二步：执行并给出可用结果

确认后，CLI 展示上传、入库、准备检索服务、验证结果的进度。最终必须检索到样例中的指定内容，才算初始化成功。

拟议输出：

```text
初始化成功，已检索到样例内容。

本次新建：
  知识库 cli-demo   index ID: idx-example
  检索服务         agent ID: aid-example

继续检索：
  kscli search --agent-id aid-example --agent-version beta --query "样例介绍了什么？"

知识库仍在运行，退出 CLI 不会停止其规格计费。
如不再需要，可删除本次新建知识库：
  kscli kb delete --index-id idx-example
```

真实输出使用实际 ID，并带上必要的工作空间参数。清理列表同时列出本次新建的检索服务等资源，解释它们的用途；不会在清理命令中自动添加确认参数。

首版只完成检索，不自动创建问答服务或发布服务。后续使用自己的资料时，输出的知识库 ID 可直接用于同步。

### 重复执行和失败

| 情况                                     | 用户看到的行为                                     |
| ---------------------------------------- | -------------------------------------------------- |
| 再次执行 init，已有资源可确认归属        | 复用资源，不重复创建知识库，不再次要求确认新建费用 |
| 已有同名知识库，但无法确认属于本次初始化 | 明确说明冲突，请用户换名称；不擅自接管             |
| 文件上传失败，还没建库                   | 报告失败步骤与已完成操作，可重新执行               |
| 知识库已创建，后续检索失败               | 明确列出已创建资源、持续计费提醒和清理方法         |
| 无法判断上次请求是否已经创建成功         | 先核对资源；无法确认时停止，不通过重复创建尝试修复 |

退出命令、关闭终端和初始化失败都不代表云端资源已删除。

## 4. 日常维护：先看变化，再同步

用户已经有一个知识库，希望让其中的一部分资料跟随本地目录更新。

```sh
kscli doc sync --dir ./docs --index-id idx-example --dry-run
```

拟议输出：

```text
同步目录：./docs
目标知识库：idx-example

新增  1 项   guide.md
更新  1 项   faq.md
不变  8 项
保留  1 项   old.md（本地已移除，本次未启用远端删除）

更新将用新版本替换旧索引内容，需要确认。
本次预览未修改任何资料。
```

用户确认后，执行同一范围的同步命令并加上 `--yes`。仅新增、没有替换或删除的同步不额外要求破坏性操作确认。文件导入涉及的模型调用仍可能收费，计划中应提示。

### 同步规则

| 本地变化                        | 默认行为                                     |
| ------------------------------- | -------------------------------------------- |
| 新增文件                        | 上传并等待入库                               |
| 内容修改                        | 新版本入库成功后，再移除旧索引版本；需要确认 |
| 内容没有变化                    | 跳过，不重复上传                             |
| 本地删除文件                    | 保留远端，明确提示                           |
| 本地删除，并显式启用 `--delete` | 展示待删除清单，确认后删除                   |
| 文件改名                        | 按新文件与旧路径分别处理；不承诺自动识别改名 |

**同步只管理由这个目录同步过程建立的那组文档。** 同一个知识库中，手工上传或其他目录管理的资料不会因为 `--delete` 被删除。

删除只移除知识库中的索引文档，数据中心源文件仍保留。删除全部文档也不等于删除知识库，不能据此认为知识库规格计费已停止。

### 为什么保留一份本地同步记录

CLI 会在目录下保存同步记录，用来记住“这个本地文件对应哪份远端文档”。用户通常无需编辑它，CLI 也不会将它上传为知识库内容。

- 日常使用时保留这份记录，后续同步才能准确判断变化。
- 在 CI 中使用时，需要持久保存记录，同一组资料同时只能有一个同步任务写入。
- 记录丢失时，CLI 可以尝试核对远端标记，但不能保证完整恢复所有历史路径，也不会猜测应删除哪些文档。

### 同步失败时的体验

新版本上传或入库失败，旧版本继续保留；过程中已经成功的步骤会被记录，下次执行先核对再继续。

如果本地目录读不全、远端清单不完整、对应关系有歧义，CLI 会停止并指出问题。不会将“没读到”当成“应该删除”。一次同步失败时，会明确报告已完成、未完成的项目，不输出“全部成功”。

## 5. 助手如何知道 CLI 会什么

普通用户无需记住 `--introspect`。它主要用于让 AI 助手读取当前安装版本的命令说明。

| 助手想知道什么                 | 查询方式                      |
| ------------------------------ | ----------------------------- |
| 当前 CLI 有哪些能力            | `kscli --introspect`          |
| 文档管理支持哪些操作           | `kscli doc --introspect`      |
| 同步需要哪些参数、是否需要确认 | `kscli doc sync --introspect` |

返回内容包括命令用途、参数、示例、鉴权方式和风险说明。查询本身无需登录，不执行业务操作，也不返回用户凭证或知识库内容。

它能减少参数猜测，但不承诺表达所有复杂参数组合规则；实际执行仍会校验。现有 `--help` 继续供人阅读。

## 6. 个人知识库 Skill 的体验

Skill 把上述能力组织成自然语言工作流，通过现有 Skill 安装渠道交付，不要求用户学习新的工具体系。

**用户：**“帮我体验一下知识库。”

**助手：**检查当前 CLI 能力和配置，展示初始化计划，说明持续计费与免费额度限制。用户明确确认后才创建；成功后给出结果和清理指引。

**用户：**“把这个目录同步进去。”

**助手：**明确目标目录和知识库，先预览新增、替换、保留或删除的文件。需要替换或删除时解释范围并获得确认，再执行。

**用户：**“体验结束了，帮我清理。”

**助手：**列出本次新建的资源与删除后果，经确认再删除。之前就存在、只是复用的知识库不列入默认清理范围。

Skill 的参数参考与 CLI 能力说明来自同一份数据，CLI 更新后同步生成，减少文档与实际命令不一致。助手不能因为用户想“体验”就自行推断用户已经同意持续费用。

## 7. 计费提醒的完整设计

这是一项贯穿创建、使用和退出的设计，不只是在 README 加一句话。

| 时机                         | 用户必须知道什么                                   |
| ---------------------------- | -------------------------------------------------- |
| init 或直接 kb create 创建前 | 创建后持续按时长计费；免费额度有限制；需要明确确认 |
| 创建成功后                   | 哪个知识库已创建；仍在运行；怎样停止规格计费       |
| 创建后发生失败               | 失败没有自动删除资源，列出实际资源和清理办法       |
| 复用已有资源                 | 没有新建知识库，但已有知识库的费用不会因此停止     |
| 查看清理指引                 | 删除知识库会永久清除其中数据，操作需要单独确认     |

完整提示采用以下口径：

> 知识库创建成功后，即使不进行检索，也会持续按运行时长计费。标准版的一次性 720 小时免费额度由多个知识库共享，新用户开通服务后 30 天内有效；模型调用费用另计。当前账户剩余额度尚未核实，请以控制台为准。体验结束后，请删除不再需要的知识库以停止其规格计费。

政策依据为 2026-09-24 核对的[官方计费说明](https://help.aliyun.com/zh/model-studio/billing-for-knowledge-base)。发布前应再次核对。CLI 不将“720 小时”描述成每个知识库都能重新领取，不根据创建时间推算实际剩余额度，也不承诺免费额度用完会自动停服。

本期不做账户余额查询、费用估算、到期通知或自动删除。创建和清理各自需要确认；确认创建不等于授权未来删除。

## 8. 本期范围与设计取舍

| 选择                     | 原因与代价                                           |
| ------------------------ | ---------------------------------------------------- |
| init 先完成样例检索      | 成功标准清楚，所需资源较少；完整问答初始化留到后续   |
| 创建前确认，沿用 `--yes` | 人和助手都能看到费用后果；比直接创建多一步           |
| 本地记录配合远端标记     | 便于核对与恢复；CI 需要保存状态，不支持随意丢弃记录  |
| 新版本就绪后移除旧版     | 上传失败时旧内容仍可用；切换期间可能短暂存在两个版本 |
| 删除限定在当前同步组     | 不误删同库其他资料；不是整个知识库的全量镜像工具     |
| 不自动识别改名           | 避免同内容多文件被错误合并；改名可能产生一次重新上传 |

本期不包含 eval 评测、自动计费治理、音视频目录同步、多机器同时写同一同步组、知识库复制或完整导出恢复。

## 9. 产品验收

1. 已具备凭证和工作空间的新用户，通过 init 完成首次成功检索，无需到控制台抄知识库或服务 ID。
2. 在可能新建计费知识库前，用户能看到费用说明并明确确认；失败也能找到遗留资源。
3. 同一初始化再次执行不重复建库；同一目录内容不变时再次同步不重复上传。
4. 用户可以在执行前看到准确的新增、替换和删除范围，其他来源的资料不受影响。
5. 同步中断后可核对并继续；无法确定状态时停止，不假装成功。
6. 助手能够发现实际支持的命令，并正确处理费用确认与删除确认。
7. 所有面向用户的提示均提供中文和英文；终端和 AI 助手获得一致的结果含义。

关注指标为首次检索耗时、初始化成功率、重复执行新增资源数、无变化同步上传数，以及创建后失败时资源清单的完整性。首次检索耗时应记录实测基线，不在 API 时延未知时承诺固定分钟数。

## 10. 进入开发前需验证的服务能力

以上是产品目标。正式交付前仍需真实环境验证两项条件：

- 上传后的源文件与知识库里的索引文档能够可靠对应，避免替换或删除错误对象。
- 新旧版本能够短暂共存，以实现“新版本可用后再删旧版”。

如果验证不通过，需调整同步设计并回到本稿说明用户行为变化，不能在实现中默默改成先删除旧文档。
