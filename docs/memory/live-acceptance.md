# Memory 用户主干 live 验收

本仓验收范围为真实云端 CLI 和真实云端受控宿主。dsh/Skill 实际 Agent 会话不在本次验收范围；本文保留其手工测试协议供宿主侧使用。受控宿主通过不代表真实宿主已验证；mock 服务响应或固定 LLM 输出不算 live。

## 运行

根目录 `.env` 配置 `DASHSCOPE_API_KEY` 和 `BAILIAN_WORKSPACE_ID`，账号需已开通 Memory。默认库主干不依赖 `BAILIAN_E2E_MEMORY_LIBRARY_ID`。测试使用随机合成 user_id，不使用个人身份文件。

```sh
node tools/test-memory-journeys.mjs --layer cli
# 真实云端 + 受控宿主；curator 需要可访问的模型
BAILIAN_MEMORY_CURATOR_MODEL=qwen3.8-max node tools/test-memory-journeys.mjs --layer plugin
# 两组顺序运行，八条必跑项通过即为本仓验收 PASS
BAILIAN_MEMORY_CURATOR_MODEL=qwen3.8-max node tools/test-memory-journeys.mjs
```

退出码：0 表示所选层必跑项全部 PASS，1 表示失败，2 表示缺少前置条件或有未验证项。普通 `vp test` 默认不启动新 journey；严格入口显式开启 `BAILIAN_MEMORY_JOURNEYS=1`。模型配置缺失不能降级为固定回答并宣称自动整理验收通过。

每次严格运行在 `test/output/memory-acceptance-<timestamp>/` 写 `summary.md/json` 和 Vitest JSON；具体步骤与资源清单位于各 journey 的 evidence 文件。只记录合成测试内容，不记录凭据。报告分别列出 CLI / controlled-host / real-host 证据。

## 用户路径与判定

| ID  | 用户路径           | 云端或受控宿主硬断言                                                         | 真实 Agent 会话补验                                                    |
| --- | ------------------ | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| J1  | 首次启用并记住偏好 | 消息抽取非空终态，节点可读，问题不含答案仍召回                               | 未授权零上传；确认启用后保存成功；不能把提交回执说成已保存             |
| J2  | 新会话回忆         | 每次独立 CLI 进程，只传相同 user_id；对照身份无交叉命中                      | 新会话不带上一轮对话，回答引用真实召回事实                             |
| J3  | 纠正长期偏好       | 原事实可召回，再抽取纠正，新事实可列举和搜索                                 | 只把新事实作为当前偏好；允许旧事实作为历史存在                         |
| J4  | 遗忘后重新记住     | 删除状态/列表/检索共同验证，保留对照事实，新的写入事件恢复召回               | 遗忘需确认；新会话不再使用旧事实；显式工具再次记住须真实提交           |
| J5  | 形成和演进画像     | 专用模板初始为空，联合抽取出现属性，纠正后属性更新，模板自清                 | 回答采用最新画像；单用户画像删除能力边界准确说明                       |
| J6  | 暂停、重启、恢复   | 暂停持久化，重建生命周期后零自动调用，恢复保持身份且不补传暂停对话           | 真正重启 dsh 后 paused 保持，恢复前不调用云端记忆                      |
| J7  | Skill/插件共用身份 | v2/v3 往返保留画像绑定；同一身份可跨入口读写；Workspace 不匹配拒绝           | 安装 Skill 的真实 Agent 能理解 v3 配置并继续使用已有画像               |
| J8  | 自动整理及写入恢复 | 真模型选择 commit/skip；真实异步写入终态；恢复任务；同轮显式保存抑制自动提交 | 宿主事件触发正确；使用真实持久化 domain 重启后仍可恢复；临时信息不保存 |

J1–J5 CLI 位于 `packages/commands/tests/e2e/memory/journeys`。J6–J8 位于 `packages/bailian-memo-dsh/tests/journeys`。故障注入（挂起、取消、并发刷新、重复提交）在插件回归单测中单独执行。

## 宿主侧手工测试协议（本次范围之外）

需要可启动的 dsh 0.2.1 兼容宿主、可用主模型/辅助模型、加载本工作区产物的 memo 插件，以及安装当前 `bailian-memory` Skill 的宿主。必须使用测试专用 HOME、dsh profile 和云端测试身份，不能覆盖开发者个人配置。不得仅运行默认 dsh profile 冒充隔离验收。

1. 构建插件，按宿主支持的隔离配置方式安装本地包；记录 dsh 版本、插件版本、模型和运行时间，不记录凭据。确认设置中 Workspace 与测试身份绑定相同。
2. J1：全新会话先说“我喜欢徒步”；拒绝启用时确认无 Memory 上传。随后明确启用并要求记住，再等终态与服务端回读。
3. J2：新建不含历史对话的会话，只问“我喜欢什么运动”；比对工具/召回事件和回答。独立测试身份作为负对照。
4. J3：更正为游泳，新建会话再次询问，检查最新事实及回答。不要以回答自然为通过标准。
5. J4：另存书法作为对照，只遗忘运动事实；确认范围后删除，验证新会话无该事实而书法仍在。再次要求记住原句，核对新的 event_id 与云端结果。
6. J5：选用本次创建的画像模板，开启抽取，保存并纠正偏好，检查属性值。CLI 无单项画像删除命令；插件画像值精确删除另列实链路门槛，不以删除模板替代用户遗忘。
7. J6：暂停，关闭并重启宿主，提交一条新的合成事实；核对零记忆请求。恢复后新写另一事实，暂停期间的事实仍不存在。
8. J7：退出宿主，使用安装当前 Skill 的另一个测试 Agent 复用该身份；验证画像引用仍在并读写。改为错误 Workspace 应失败，不能重建身份绕过错误。
9. J8：普通长期偏好触发真实辅助模型；临时要求被跳过。显式 remember 后同轮不二次整理。获得提交回执后重启宿主，使用真实 storage-domain 检查任务恢复及终态。
10. 等待所有已提交事件完成后，仅清理测试身份的节点和本次创建的模板；记录无法清理的资源。报告每条 journey 的真实宿主 PASS/FAIL/BLOCKED 与证据位置。

## 失败及清理

- 查询最终一致性可有限轮询；不自动重发结果不明的写入。
- 删除不能仅凭搜索空结果判定；必须结合节点状态、列表和对照事实。
- 数据隔离是 user_id 范围验证，不宣称它构成服务端认证边界。
- 异步事件未终止、清理失败或权限不足必须保留资源清单，不能将它们吞掉后输出 PASS。
- 服务端错误保留原始语义；环境缺失为 BLOCKED，调用执行后断言失败为 FAIL。
- 多模态、skill 类型与跨库规则是额外验收组，需预置 fixture/白名单，不计入默认个人记忆主干覆盖。
